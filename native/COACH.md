# AI coach and guided Watch workouts

## Use the app

1. In iPhone Settings → AI coach, save your personal OpenAI API key. Gyma uses `gpt-6-luna`; the API project must have access and API billing. Keys stay in this iPhone's Keychain, excluded from JSON backups and Watch sync.
2. Open Coach and check in with energy and soreness for chest, back, legs, shoulders, arms and core. New check-ins default every group to None. Tell the coach your goals, equipment and preferences in the check-in notes or conversation. Messages, the current check-in, exercise catalog and summaries of up to six completed workouts are sent directly to OpenAI when you request a reply. Past check-in notes are excluded. API requests use `store: false`.
3. Discuss changes to the draft. Each exercise has working sets, reps, optional target kilograms, rest seconds and a reason. Gyma validates the complete plan against the exercise library before saving it. Missing loads mean you choose the load; zero means bodyweight.
4. Tap **Accept workout plan** to close the planning chat and return to Overview. The Coach tab has no Start or Finish workout controls. Today's accepted plan can be started from Overview or the Watch. Before either start, review energy and soreness; the final timestamped readiness check is stored with that workout. Watch start waits for a phone acknowledgment, expires after five minutes, and cannot cross midnight or create a second session. Plans default to their creation day; earlier drafts without a scheduled date use that day too. Revising a plan requires accepting again.
5. On Watch, the first exercise opens with editable **KG** and expected **REPS**. Choose them, tap **Start Set**, perform it, then tap **Finish Set**. Adjust completed reps with the **− / reps / +** buttons and tap **Confirm Reps**. On the next screen, scroll the kilogram wheel with the Digital Crown in **0.5 kg steps**, then tap **Confirm Weight**. The back arrow returns to reps without losing the weight. Gyma saves the set only after both confirmations. The same rep buttons and kilogram wheel are used when preparing a set or changing the next set during rest. Existing weights between the half-kilogram steps stay selectable. Rest starts after confirmation, except after the final target set of an exercise. Tap **Dismiss** when you resume; it records the elapsed rest using the Watch tap time and begins the next set after confirmation from iPhone. Change the next set's weight or reps during rest if needed. The next exercise opens with its own preparation controls.
6. Allow Gyma's workout access when opening an active session on Watch. Gyma uses a native strength-training `HKWorkoutSession` to keep the session running with the wrist down and expose the system workout icon for returning to the app. The display can still dim or follow watchOS/user settings. Gyma does not read your Health history or save a duplicate Health workout; the system may generate health samples during the session.
7. **Rest vibration is on by default**, independent of notification permission. During the native workout session, six full notification-haptic pulses spaced two seconds apart mark the rest deadline, including in the background. Later pulses stop when rest is dismissed, changed, or ended; the sequence lasts about ten seconds. WatchKit controls individual pulse intensity and duration. The app requests no notification sound; turn on Watch Silent Mode to mute any system tones attached to built-in haptics. The exact Mindfulness/Breathe pattern is not exposed to apps. If workout mode is unavailable, Gyma uses foreground haptics plus an optional silent visual notification fallback. Rest remains visible until **Dismiss**. Watch settings includes **Test vibration**, the vibration toggle and Finish workout early. A settings badge flags workout-mode permission or alert issues; open settings to read the details.

Inside the iPhone workout, **Ask coach** opens a separate conversation using live exercises, targets, actual sets, rest and readiness. Ask for advice, different target weights/reps/rest, or a replacement for an exercise that has no logged sets. Proposed changes have an explicit **Apply change** action; stale responses and proposals are rejected if the workout changed. Completed sets remain intact. The coach cannot start or finish workouts through chat.

History records readiness separately from the planning check-in. Exercise Progress shows energy and that exercise's muscle soreness beside each session. Older workouts without readiness stay unrecorded, rather than being treated as no soreness. Up to six recent completed sessions, including readiness and actual performance, are sent as context to the coach; this is historical context, not automatic model training or proof that a condition caused progress.

The phone remains the authoritative store. Watch changes are saved to a durable outbox and wait for a phone receipt before another mutation. Keep the paired iPhone available. A disconnected Watch is not an independent multi-set workout recorder.

## Validation

Shared tests cover legacy data decoding, acceptance and revisions, invalid AI plans, structured response parsing, original/actual rest durations, delayed and duplicate commands, progress in bounded snapshots, persisted Watch set phases, and rest-haptic scheduling. The existing `swift.yml` workflow tests GymaCore and builds both native apps.

Device checks:

- Add/replace/remove a key. Generate a plan, request different reps/rest/exercises, accept, relaunch and start. Verify acceptance closes the chat, today's accepted plan appears on Watch, and starting from either device records energy and all soreness groups exactly once. Check midnight, stale/replaced plans, delayed delivery and duplicate start commands.
- Test invalid key, unavailable network and retry; the current draft and pending message must survive without duplicate chat messages. Restoring a backup or replacing a check-in during a request must discard a stale response.
- Select kilograms before starting, tap Finish Set, use − for one fewer actual rep and Confirm Reps, scroll the kilogram wheel to a half-kilogram value, then Confirm Weight. Check Back preserves values and the weight wheel retains an existing quarter-kilogram value until changed. Verify actual performance saves once, rest appears, Dismiss begins the next set, and the next exercise appears after the target number of working sets. Relaunch while preparing, lifting, reviewing reps, reviewing weight and awaiting confirmation; values and phase must remain intact.
- Acknowledge rest early and late. History should show actual versus original planned seconds. Extend rest on iPhone; the original plan remains recorded.
- Inside an active workout, request tips, a target adjustment and an unstarted exercise replacement. Apply each proposal and check Watch updates; changes to completed sets must be rejected. Log a Watch set while waiting for an AI reply and verify stale advice/proposals cannot overwrite it.
- Test vibration with Watch foreground, wrist down/background, Focus enabled, and notification permission denied. Allow Health workout access, check the workout icon, and verify Test vibration. Deny Health access separately and check the fallback/error state. Check no duplicate deadline taps on reopening or refreshing, and verify workout mode stops on phone finish or a queued Watch finish.
- Reconnect after a queued set or rest acknowledgment. Review rejection messages if the phone session changed meanwhile. Reopen older data and restore a previous-format JSON backup.

Live AI calls need a user-supplied API key. Physical pairing, haptic delivery and on-device layout require an iPhone/Watch check after signing and installing the combined IPA locally. Workout mode requires the signed Watch provisioning profile to grant `com.apple.developer.healthkit`. The custom iLoader now enables that capability when the Watch bundle requests workout runtime and checks the profile before signing. This capability update needs the updated local installer; subsequent ordinary app changes do not require rebuilding it.

API references: [GPT Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
